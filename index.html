适用于 Windows 10 / 11 LTSC 及移除 Xbox 组件的系统

?脚本解决什么问题(详细说明)

现象

在 Windows 10/11 LTSC 上,每次连接手柄(有线插入、蓝牙连接,或按下手柄上的 Xbox 键)的瞬间,屏幕都会弹出这样的对话框:

需要新应用以打开此 ms-gamebar 链接

这个弹窗无法通过「不再提示」关闭,每次连接手柄都会重复出现,非常烦人。它只是一个提示,不影响手柄本身的按键、震动等功能。

根本原因

  • 在普通版 Windows 10/11 中,系统内置了 Xbox Game Bar(游戏覆盖层)。注册表 HKEY_CLASSES_ROOT 下注册了 ms-gamebar:// 和 ms-gamebarservices:// 两个协议,指向这个应用。
  • 当检测到手柄连接(或按下 Xbox 键)时,Windows 会调用 ms-gamebar:// 协议,尝试拉起 Game Bar 来显示手柄相关的提示界面。
  • LTSC(长期服务版)面向精简场景,默认移除了 Microsoft Store、Xbox 全家桶等组件,这两个协议在注册表里完全没有处理器。
  • 于是系统调用协议时找不到任何能打开它的应用,触发了 Windows 的兜底行为——弹出「需要新应用」对话框。这就是弹窗的全部来由。

fix.bat 做了什么

  1. 在 %LocalAppData% 写入一个内容为空的脚本 ms-gamebar-noop.vbs(只有一行注释,运行即退出,不做任何事)。
  2. 用 reg add 在当前用户注册表(HKCU\Software\Classes)中为 ms-gamebar 和 ms-gamebarservices 两个协议补上处理器定义:URL Protocol 标记、NoOpenWith(禁止系统弹"选择应用"),以及打开命令。
  3. 打开命令指向 wscript.exe //B //Nologo <空脚本>。wscript.exe 属于 GUI 子系统程序,从进程创建起就不分配控制台窗口;而 //B //Nologo 保证不显示任何脚本错误和横幅。所以协议被调用时,整个过程静默、瞬时、零窗口。

效果

修复后,连接手柄时系统调用 ms-gamebar:// 协议会"成功打开"这个空处理器——静默执行、立即退出。系统认为应用已正常启动,自然不再弹窗。整个过程你完全感知不到:没有弹窗、没有闪框、没有后台残留。

为什么不直接删掉什么?

这个问题的成因是"缺东西"而不是"多东西",所以修复方式是补上一个无感的占位处理器,而不是删除或禁用什么。也因此修复是纯增量、可逆的:运行 undo.bat 删除这几个注册表项和空脚本,系统就回到修复前的原始状态。

✦常见问题

需要管理员权限吗?

不需要。修复只写入当前用户的注册表(HKCU),每个 Windows 账户需各自运行一次 fix.bat。

有风险吗?如何还原?

新增的只是两个协议的空处理器,不影响系统其他功能。运行 undo.bat 即可完整还原(删除注册表项和空脚本)。

浏览器提示 .bat 有风险?

脚本是明文文本,可以用记事本打开查看全部内容再决定是否运行。它只做两件事:写一个空 .vbs 文件到 %LocalAppData%,以及用 reg add 写入协议注册。

为什么我的系统没有 Game Bar?

Windows 10/11 LTSC(长期服务版)面向精简场景,默认不包含 Microsoft Store、Xbox Game Bar 等组件。家庭版/专业版用户通常不会遇到此问题。
